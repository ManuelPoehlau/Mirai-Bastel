## 1. Requirement

1. While modelling or morphing a face in the normal Worklight view, eyes look like the lab's eye: refracting cornea,
   the custom iris image (radial fit), the soft limbus, a wet highlight.
2. Every other object draws exactly as today; with no eye in the scene the Worklight output is byte-identical.
3. An eye is placed like any object (move / rotate / scale, select, hide, duplicate, delete, Undo) and its values are
   saved with the scene.
4. The preview can be switched off (then the eye draws as a plain Worklight object).
5. Cost is measured on the reference PC; the preview may not change the cost of a scene without eyes.

## 2. What exists (facts)

- **Lab (frozen state 2026-11-14):** `eye_geometry.py` (eye meshes, lab units: 1 = sclera radius = 12 mm),
  `cornea_optics.py` + `refraction_shaders.py` (V2 / V3 ray model and GLSL, GPU parity), `iris_fit.py` (radial remap,
  GLSL twin, sidecar), `limbus_model.py` + `limbus_shaders.py` (L1–L3, overlap, asymmetry, colour source, the L3 fast
  path), `shaders.LIB_SRC` (GGX, Schlick, split-sum, studio, colour path). Every GLSL function has a NumPy twin and a
  parity test. Measured on the reference PC (MEASURED [RPC]).
- **In P1b / P1c the iris mesh is never drawn** (V2 / V3): the cornea pass finds the iris analytically (cone `z = a +
  b r`). The cornea and sclera meshes are only raster footprints; the shading uses analytic spheres.
- **Production:** `SceneObject` has `material` (AD-024) and `texture` (AD-026) and `__slots__`; the scene format is at
  v8 (`core/serialization.py`, versions chosen by content). `Viewport.render()` draws the edit mesh (`render_mesh`, or
  a surface provider's mesh) and then every `object_entries` entry through `RenderMesh.render()` →
  `GLRenderStore.draw()`; overlays follow. The Worklight light comes from `Viewport.light_uniforms()` (light rig,
  camera-relative). The GPU picker draws the same VertexLists with its own program (precedent for a foreign pass).
- **Audit §4.2** already recommends the seam: a pass *outside* `GLRenderStore.draw()` that draws a store's VertexList
  with its own program, through one public, behaviour-free binding accessor on the store.

## 3. Options for the eye's representation

| | Representation | For | Against |
|---|---|---|---|
| **E1** | **One object, one mesh: the eyeball's outer shell** (sclera sphere + corneal cap, shared limbus ring); iris and pupil are analytic in the shader | one entry, one draw, picking / selection / transform / hide as any object; matches how P1b / P1c already work (the iris mesh is not drawn) | the shell must stay the analytic shape (§4.3) |
| E2 | A group of three objects (sclera, cornea, iris) as in the lab | each part a separate entry | three objects to keep in sync and pick; the iris mesh is only needed for V1 (no refraction), which the preview does not use |
| E3 | The user's own eye mesh, parts marked | any shape | rejected (D-L7: parametric); the analytic refraction only fits a sphere + cap |

**Recommendation: E1.**

## 4. Data model (Core field, CORE_V1_FREEZE §7; precedent AD-024)

### 4.1 `SceneObject.eye: EyeSpec | None`

A frozen dataclass in `src/core/scene.py`, data only, validated (`ValueError`), `None` = not an eye. Eye-local units:
1 = the sclera radius (the object's scale sets the size).

| Group | Fields (lab defaults) | Notes |
|---|---|---|
| Anatomy | `cornea_radius` 0.65, `limbus_radius` 0.49, `iris_root_z` 0.80, `iris_concavity` 0.03, `pupil_radius` 0.16 | the lab's `eye_geometry` constants; the posterior cornea / chamber angle derive from them (`CorneaGeometry`) |
| Iris image fit | `fit_pupil`, `fit_limbus`, `hold_outer_color` (None = planar) | the sidecar's values move into the scene; the image itself is `SceneObject.texture` (AD-026 path, no second path) |
| Limbus look | `limbus_level` L0–L3, `colour_source` shader / image, `limbal_colour` (sRGB), `band_mm`, `strength`, `normal_mm`, `falloff`, `overlap_mm`, `asymmetry` | P1c's settings, "alles als Einstellungen" |

Which of these are saved per eye and which are global view state is **Q-E3**; the proposal in §6.

### 4.2 Scene format v9

`"eye": null | {...}` per object; v9 is written when any object is an eye (the existing "version by content" rule);
v1–v8 load with `eye = None`; an invalid eye makes the file invalid (as an invalid material). `replace_scene`,
duplicate and mirror copy carry the spec (a mirror copy mirrors nothing in it — an eye is symmetric about its axis).

### 4.3 The shell mesh is generated, not edited

- `src/mirai/eye_object.py` builds the shell from the anatomy (the lab's `sclera_mesh` + `cornea_mesh` joined at the
  ring, no pole fan at the front; ≈ 3.4 k faces at the lab's 64 segments: 2 368 sclera + 1 024 cornea, `PROVISIONAL`).
- **Component editing of an eye is refused** with a status line ("Auge: Form über die Augen-Werte", proposal; Q-E5).
  Object transforms, hide, group, duplicate, delete work as for any object. Changing an anatomy value replaces the
  shell (one Undo step, a command shaped like `ObjectMaterialCommand`, holding the old and new mesh).
- Morphs and the rig: eyes are rigid and not morphed; parenting an eye to a head bone is AD-028's business, later.
  *(2026-11-18: built — an eye links to its own eye bone, [AD-036](AD-036-EYES-TEETH-AND-LIDS-ON-THE-RIG.md) §5.)*

## 5. Render path

### 5.1 The eye pass (audit §4.2, option B)

- New `src/viewport/eye_pass.py` + `eye_shaders.py`: the lab's GLSL (LIB_SRC parts, REFRACTION_LIB_SRC, iris_fit,
  LIMBUS_LIB_SRC) and their NumPy twins, moved as source (§8).
- **One program per variant for the shell:** per fragment the eye-local position (inverse model matrix) decides
  *cornea* (on the cap) or *sclera*. Cornea: P1b V2 trace (V3 selectable) + P1c terms; sclera: P1c sclera. Texture
  reads stay in uniform control flow (as in the lab). The L3 fast path comes along.
- GL state explicit and restored, as the lab's passes: opaque, depth test + write, no blending, back faces culled.
- `GLRenderStore` gains one public, behaviour-free accessor to bind the entry's VertexList and camera / model uniforms
  for a foreign program (audit §4.2 "store binding accessor"); the Worklight path calls the same code as today.

### 5.2 Viewport switch

- `Viewport.set_object_entry(..., eye=EyeDraw | None)` (the resolved spec + iris texture path); the edit mesh gets the
  same via its setter. `render()` draws an entry with an `EyeDraw` through the eye pass when the preview is on, else
  as today. Draw order unchanged; overlays (wire, selection, hover, gizmo) draw after, unchanged.
- **Gates:** with no eye entry, `test_gl_face_data_layout.py`, `test_gl_shading.py`, `test_gl_texture.py` stay
  byte-identical, the full GL and picking suites pass, D3 unchanged.

### 5.3 Light and reflection in the Worklight

- The eye is lit by **the Worklight's own key / fill / ambient** (`light_uniforms()`), not by the lab's studio, so it
  sits in the scene's light and follows `L`-drag.
- The wet look needs something to reflect. Proposal: the cornea reflects the **procedural studio cube** (lab T-C;
  RGBA16F 128², built once and cached as in the lab) rotated with the Worklight's key; the sclera uses T-B (key GGX).
  A cheaper tier without the cube (key highlight only) is a setting. **Q-E4.**

### 5.4 Colour path (D-L3, for the eye pass only)

The Worklight is display-referred; the lab shades in linear light with exposure and Reinhard, then encodes sRGB. Mixed
in one image, an eye could look brighter or darker than the skin next to it. Proposal: the eye pass keeps the lab's
linear path and maps it so that a **neutral Lambert surface lit by the Worklight key matches the Worklight's own
output for the same base colour** (a calibration test: grey sphere in both paths, ≤ 2 / 255 at normal incidence).
If that match is not reachable without changing the Worklight, the eye pass gets an exposure offset as a setting and
the mismatch is reported. `PROVISIONAL`; measured in E-2.

### 5.5 Selection, hover, picking, hidden

- Picking: unchanged (the shell is a normal mesh in the ID buffer).
- Selection: overlays as for any object; a selected eye additionally gets AD-024's selection tint on the sclera
  albedo (`PROVISIONAL`).
- Hidden / isolate: as for any object. A Reference eye draws as a Reference (Worklight), no preview.

## 12. Addendum 2026-11-16: eye gaze (view state, `PROVISIONAL`)

*(2026-11-18, [AD-036](AD-036-EYES-TEETH-AND-LIDS-ON-THE-RIG.md) §5.2: **in a pose** the gaze drives the eye bones of
linked eyes (their channels replaced while it is on; the user's pose untouched), so lid points weighted to them follow;
the clamp, the pad and the mouse plane are taken in the head-carried frame; the lid frame is the placement carried by the
eye bone's parent. **At rest** everything below holds unchanged.)*

**Request (Manu, 2026-11-16):** "ich brauche eine Möglichkeit, die Augen Blickrichtung per Maus steuern zu können. Auch
die Option, dass die Augen in die Kamera gucken (ich drehe den viewport, aber gollum guckt mich dabei immer an)".

**Built:** `mirai/eye_gaze.py` (pure math), `DisplayState.eye_gaze` (`GazeState`), `ObjectController.gaze_target` /
`sync_gaze` (the drawn eye matrices in `sync_views`, re-synced by the frame tick when the point moves),
`Application.set_eye_gaze` / `set_eye_gaze_angles` / `eye_gaze_angles`, the section "Blick" in the panel "Auge"
(`gui/eye_model.py`, `gui/eye_panel.py`). Tests: `tests/test_eye_gaze.py`, `test_gui_eye_model.py`,
`test_gui_imgui_window.py` (panel + eye pass with a turned eye, GL state).

- **Rule:** every drawn eye (selected or not) looks at one world point; each turns about its own sclera centre by the
  shortest rotation from its own rest direction (its object rotation = the primary position, Listing's law, no added
  roll), clamped to `MAX_GAZE_DEGREES` = 50° (a camera behind the head never turns the eyes into the skull). Both aim at
  the same point, so they converge on a near one.
- **Modes:** `rest` (the object rotation; draws exactly as before), `camera` (the camera's eye point), `mouse` (the point
  under the cursor on a plane facing the view `focus` eye radii in front of the eyes; the cursor over a panel or outside
  keeps the last point), `target` (a fixed world point: the gaze pad, or switching from `mouse` freezes the current
  point). `focus` (default 25 eye radii ≈ 30 cm at the reference eye) also sets the pad's distance; changing it in
  `target` keeps the direction.
- **View state, like the preview (Q-E3):** the object transforms, the file and the Undo stack never change. No keys
  (D-L9): the panel only. The CPU pick caches keep the object's own rotation (an eye shell is a sphere about the turn

**How the key's path is found** (`eye_optics.iris_light_path`). Incident ray, cornea normal and refracted ray lie in
one plane through the cornea's centre, so the entry point is a single angle in that plane: a root of "the refracted ray
misses the iris point", found by secant steps from the straight path's exit (6 steps; the two neighbours of the finite
difference start from that solution, 3 steps). A plain fixed-point iteration was tried first: it needed more than 12
steps at a grazing key and gave a wrong crescent at 3. No root, a key behind the entry, or a residual above 1e-4 means
the key cannot reach the point (beyond the caustic): no key light there. **Checked against a forward ray trace**
(`test_eye_iris.py`: a parallel beam through the cornea onto the iris, keys at 0°, 40°, 70°, 80°): the model's
irradiance agrees within 15 % / 0.08 in the bins away from the steep edges, the far-side crescent at a grazing key is
over 3 × the unrefracted key's cosine there, and the unlit zones agree. With a frontal key the effect is small (the
cornea focuses about 1.3 × evenly); it shows when the key comes from the side (`L`-drag).

**The derived height** (`eye_optics.iris_height`, Manu "2 go"): luminance minus its Gaussian mean (3 % of the image
width, normalized over the iris annulus only), scaled by its RMS (2.5 × RMS = full height), flat outside the annulus
between the image's pupil edge and iris edge (the fit's landmarks, else the planar mapping's), soft over 4 %. Bright
fibres and the collarette rise, dark crypts sink; the colour zones (brown collarette, blue outer iris) do not become a
step. The eye pass builds it once per image file (path + modification time) and fit, into its own RGBA copy of the
image (`EyePass.relief_texture`, the shared texture of AD-026 untouched, filtered like `load_texture`). Known limit:
light baked into a photo (catchlights) becomes false relief; the import of phase 5 (retouching, a real height) removes
that.

**The copy.** Square, centred on the iris circle, the iris edge at 0.88 of half its width (`TARGET_SHARE`), 256-2048 px.
A pupil off the iris centre is moved onto it smoothly (the eye's pupil is centred). Two mappings:
- **flat / painted** (and a photo without the correction): the source radius scaled linearly; `fit_pupil` / `fit_limbus`
  pin the copy's pupil edge and iris edge exactly as the hand-written JSON did (`hold_outer_color` = "Randfarbe

- **frontal photo with "Brechung herausrechnen"** (default on for photos): a copy pixel stands for a true iris radius

  photo shows at A(r), linear in the apparent radius between the landmarks (the photo's pupil edge at the eye's apparent
  pupil edge, its iris edge at the eye's visible limbus). The copy is then a true-radius layout: `fit_pupil` =
  0.88 × pupil / limbus radius, `fit_limbus` = 0.88, no hold (beyond the visible limbus the copy holds the photo's
  edge colour itself). Exact for the first selected eye's anatomy at import; both landmarks stay pinned by the fit if
  the anatomy changes later.

**The landmark error (§H row 5, `frontal_error`).** Following the eye's own path (radius -> fit `share_map` -> copy ->
source): a photo at the eye's apparent pupil edge and visible limbus against the photo's landmarks; a flat image at the
true pupil and limbus radii. **Measured [C]:** flat image 0.0 %; frontal photo with the correction 0.0 % (with the
estimate's landmarks, not touched by hand, within 1.5 % on the synthetic photo); **a frontal photo without the
correction 5.5 %** - the doubled refraction: the hand-written fit pins the photo's visible iris edge to the true limbus
radius, which lies behind the limbus, so the eye's visible edge shows the photo 5.5 % of the iris radius inside its
